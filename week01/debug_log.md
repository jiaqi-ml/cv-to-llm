## 记录 1：函数只写了边界判断，忘了主逻辑（结果错，不崩）

- **现象**（实际输出，非异常栈）：
  ```
  check([3, 9, 2, 7])   -> None     期望 9
  check([-5, -1, -9])   -> None     期望 -1
  check([])             -> None     期望 None   ← 只有这组是对的
  ```
- **最小复现**：
  ```python
  def check(nums):
      if len(nums) == 0:
          return None
      # ← 到这里函数就结束了，没有循环、没有 return
  ```
- **假设**：我以为是 `champion` 初始化有问题（因为之前踩过"设成 0 导致全负数出错"的坑），所以先打印了 `champion`。
- **定位**：`champion` 根本没被打印出来 —— 说明**循环压根没执行**。把函数单独抽出来，用三组输入各跑一次，发现只有 `[]` 那组对，非空列表全部落到函数末尾、隐式返回 `None`。
- **根本原因**：把"防崩溃的边界判断"当成了"功能的全部"。文件上半部分的三段 print 版有完整的擂主循环，抽成函数时**只搬了 `if`，没搬 `for` 和 `return`**。
- **修复**：
  ```python
  def find_max(nums):
      if len(nums) == 0:
          return None
      champion = nums[0]
      for n in nums:
          if n > champion:
              champion = n
      return champion
  ```
- **以后怎么避免**：**边界判断只保证"不崩"，不保证"算对"。** 写完函数必须列一张输入表，每组都跑，不能只测一个 —— 今天正是因为只测了 `[]` 才漏掉的。

## 记录 2：复制粘贴后忘了改注释

- **现象**：程序正常运行，但注释与代码说的不是一回事：
  ```
  第 22 行  # 让 n 依次变成 4、1、9、6     ← 实际列表是 [3, 9, 2, 7]
  第 43 行  # 应该是 9                     ← 这一组实际得 -1
  ```
- **最小复现**：把上一段代码整块复制下来，只改了 `nums` 的值，没改注释。
- **假设**：我以为是 print 输出错了。
- **定位**：把 `print("示例最终擂主：", champion)` 的输出和旁边的注释逐行对照，发现对不上。
- **根本原因**：复制的时候只改了**会被执行的部分**，没改**给人看的部分**。
- **修复**：把那两处注释改成与实际一致（第 43 行改注"实际得 -1"）。
- **以后怎么避免**：**复制代码块时，注释和代码一起改。** 注释和代码不一致比没有注释更糟——以后回看会被误导，而且这种错误不会被任何工具报出来。

## 记录 3：文件名少打一个字母

- **现象**：文件存成了 `ex03_eve.py`，但计划里要求的是 `ex03_even.py`（even = 偶数）。
- **最小复现**：无——文件名错了不会有任何提示，程序照跑。
- **假设**：以为存的时候名字是对的。
- **定位**：`ls exercises/` 列目录时才发现少了一个 `n`。
- **根本原因**：文件名是手打的，没有和计划里的清单核对。
- **修复**：`mv ex03_eve.py ex03_even.py`，重跑确认输出不变。
- **以后怎么避免**：**建文件时就按计划里的名字原样复制**，别手打。文件名不会报错，只会让你以后找不到东西。
